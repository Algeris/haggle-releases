# Contributing to Haggle

*Last updated: September 5th 2026*

First off, thank you for considering contributing to Haggle!

Haggle is proprietary commercial desktop software developed and maintained by **Algeris** (https://haggle.algeris.com). While the core application source is closed-source and proprietary, our public releases repository at [Algeris/haggle-releases](https://github.com/Algeris/haggle-releases) hosts public installers, release notes, documentation, issue tracking, and community feedback.

## Contribution Terms

Contributions in the form of bug reports, feature requests, documentation improvements, integration scripts, and feedback are welcome.

By submitting an issue, feature suggestion, documentation update, idea, prompt, or other contribution via our public repositories or direct communication channels, you agree that Algeris may use, modify, distribute, commercialize, and incorporate your contribution into Haggle or any other Algeris product or service without restriction.

Please do not submit contributions or proprietary code unless you have the legal right to do so.

## How Can I Contribute?

### Reporting Bugs

Bug reports are tracked through our public GitHub repository at [https://github.com/Algeris/haggle-releases/issues](https://github.com/Algeris/haggle-releases/issues).

Before creating a bug report, please check existing open issues to avoid duplicates. When filing a bug report, please provide:

- A clear and descriptive title.
- Step-by-step instructions to reproduce the issue.
- Expected behavior vs. actual observed behavior.
- Relevant log snippets (redacting any private API keys or personal details).
- App version (e.g. `v0.1.1`) and operating system (Windows / macOS / Linux architecture).
- Screenshots or recordings if applicable.

### Suggesting Enhancements

Enhancement suggestions and feature requests can be submitted via [GitHub Issues](https://github.com/Algeris/haggle-releases/issues). When submitting a feature request, please include:

- A concise title and clear description of the proposed feature.
- The use case and how it enhances live conversation intelligence across meetings, interviews, pitches, or everyday interactions.
- Any mockups, proposed workflow steps, or architectural considerations.
